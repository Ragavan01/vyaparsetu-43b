### 3. Key Product Decisions & Trade-Offs

- **Decision 1: Deterministic Statutory Engine + Server-Side Gemini Vision (Hybrid Architecture)**
  - *Chosen Approach*: All financial math (GSTIN 15-char checksum, CGST/SGST/IGST arithmetic, 15/45-day Section 43B(h) deadlines, MSMED §16 3× RBI compound interest, and TReDS vs. informal credit arbitrage) executes in pure deterministic TypeScript, while Gemini handles unstructured invoice image extraction, anomaly explanation, bilingual drafting, and live policy search grounding.
  - *Why*: Eliminates LLM math hallucinations on financial figures and ensures the ledger, compliance calculator, and TReDS simulator remain 100% functional and auditable even if upstream AI quotas fluctuate.
  - *Alternatives Considered*: Pure LLM calculation (rejected—unacceptable numerical drift in a fintech pitch).
- **Decision 2: Zero Login Walls with Client-Side Session State + Exportable Audit Reports**
  - *Chosen Approach*: No forced signup/auth gate; newly audited invoices append cleanly to the live interactive session ledger (persisted locally in browser state with 1-click Reset to Pithampur Pilot Baseline) and export as clean JSON/text briefs.
  - *Why*: Meets the `<15 second` judge experience requirement and deploys effortlessly to Vercel with zero database provisioning dependencies.
  - *Alternatives Considered*: Full multi-tenant database + OAuth (rejected for hackathon MVP—adds friction before judges see the core workflow; slated for Phase 2 post-hackathon pilot).
- **Decision 3: Two Dedicated Server-Side Gemini Capabilities on `gemini-4-hydrogen`**
  - *Chosen Approach*: Route `/api/ai` dispatches two strictly validated modes using `gemini-4-hydrogen` via `@google/genai`: (a) `audit_invoice` with multimodal image/text input and strict `responseSchema` JSON output, and (b) `policy_grounding` with `tools: [{ googleSearch: {} }]` returning real web citations.
  - *Why*: `gemini-4-hydrogen` delivers low-latency multimodal vision + structured JSON + Google Search grounding without requiring a paid-only model gate, and avoids invalid `ThinkingLevel.MINIMAL` errors.
- **Decision 4: AI Studio Extra Tools (Max 2 Enabled, Rest Strictly OFF)**
  - *Keep ON*: **(1) Multimodal Image Analysis** (invoice photo upload audit) and **(2) Google Search Grounding** (live RBI Bank Rate, Section 43B(h), and MP MSME policy citations).
  - *Keep OFF*: **Google Maps Data** (Open-Meteo coordinates + clean corridor metrics avoid Maps billing-key friction), **Voice / Live Audio** (adds browser mic-permission friction during rapid judge demos), and **Runtime Image/Video Generation** (unnecessary for B2B finance).

#### Data Model, Provenance & State Boundaries

- **Core Entities**:
  - `InvoiceRecord`: Invoice ID, supplier/buyer names, GSTINs, Udyam MSE status (`Micro` | `Small` | `Unverified`), written credit agreement flag, invoice/acceptance dates, subtotal/GST/total amounts, line-item summary, and explicit `provenance` (`ai_extracted` | `pithampur_pilot` | `manual_entry`).
  - `ComplianceAuditResult`: Deterministic output covering GSTIN validity, MP state detection, tax arithmetic delta, statutory 43B(h) deadline (15d vs 45d), overdue days, MSMED §16 monthly compound interest (based on RBI Bank Rate), buyer tax disallowance estimate, and actionable findings.
  - `TredsSimulation`: Net cash today on TReDS vs. informal credit cost vs. delayed-wait cost, annualized savings, and working-capital days unlocked.
  - `LiveCorridorSnapshot`: Nullable weather fields (`temperatureC: number | null`, `precipitationMm: number | null`, `freightRiskLabel`) and nullable FX rates (`usdInr: number | null`, `eurInr: number | null`) with ISO fetch timestamps and explicit `status: "live" | "unavailable"`—missing readings are **never coerced to `0`**.

#### Interactive Component & State Mapping

- **Audit Studio**: File dropzone (accepts JPG/PNG/WebP up to 4 MB, validates MIME type client & server-side) + 3 one-click Pithampur sample invoices (2 generated realistic GST invoice scans + 1 export invoice). Clicking **`Run AI Audit`** posts to `/api/ai` (`audit_invoice`), displays a matching skeleton state, hydrates editable fields, runs deterministic compliance verification, and enables **`Add to 43B(h) Ledger`** or **`Simulate on TReDS`**.
- **43B(h) Ledger**: Real-time search input, segmented status filters (`All`, `Overdue`, `Due Soon`, `Compliant`), sortable columns with tabular numerals, row selection drawer showing statutory breakdown, and 1-click bilingual notice copy (`English` or `हिन्दी + Hinglish`).
- **TReDS Simulator**: Interactive range/number controls for invoice amount, buyer delay days, TReDS discount rate, and informal interest rate—recomputing all comparison bars and net savings in real time (`<16ms`), paired with copyable TReDS readiness checklist.
- **Indore Pulse**: Auto-loads `/api/live-data` on view with explicit refresh control and **`Verify Live RBI & MP Policy`** button invoking `/api/ai` (`policy_grounding`) to display current statutory references with clickable external source links (`rel="noopener noreferrer"`).

#### Security, Hardening & Automated Verification (`npm run verify`)

- **Server-Side Secret Isolation**: `GEMINI_API_KEY` is accessed strictly inside server Route Handlers via `process.env`, never shipped in client bundles, and never requested via any UI input.
- **Input Validation, Rate Limiting & Safe Rendering**: All API bodies are validated with strict Zod schemas, capped at 4 MB for base64 invoice images, sanitized against control characters, protected by an in-memory per-IP sliding-window rate limiter, and rendered with zero `dangerouslySetInnerHTML`, `eval`, or `new Function`.
- **Hardened Security Headers**: `next.config.ts` sets `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`, and a strict Content-Security-Policy (with iframe-compatible `frame-ancestors` for preview sandboxes and `X-Frame-Options` strategy documented for standalone deployment).
- **Single-Command Verification Gate (`npm run verify`)**:
  1. **TypeScript Strict Check**: `tsc --noEmit` with `strict: true` and zero unguarded `any`.
  2. **Linting**: `eslint .` ensuring zero unused imports, hook violations, or syntax errors.
  3. **Unit & Security Tests (Vitest)**: Tests deterministic GSTIN checksums, 15/45-day Section 43B(h) deadlines, §16 compound interest math, TReDS arbitrage formulas, null-safe live data handling, Zod API validation, and rate-limiter enforcement.
  4. **Static Security, Accessibility & Modularity Gate Script**: Automated audit script verifying zero `dangerouslySetInnerHTML`/`eval`/hardcoded secrets, every source file `< 280` lines, semantic landmark/label checks, and hardened headers presence.
  5. **Executive `README.md`**: Complete architecture diagram, problem-to-feature matrix, `.env.example` setup guide, and 2036 Bharat scalability roadmap.
